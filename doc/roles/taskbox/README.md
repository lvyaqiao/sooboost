## 与 mailbox 的分工（正交，勿混投）

| 通道 | 方向 | 语义 | 时机 |
|---|---|---|---|
| **mailbox/** | 任意域 → 任意域 | 动他人域文件的**声明** | 开工前投一条，投递即完成、不等批复 |
| **taskbox/** | 维护者 → 域 owner | 立项任务的**分派** | backlog 状态 assigned 时同步投递；维护者独占写 |

- 域 owner 执行 taskbox 任务时要动他人文件 → 仍按旧规投 mailbox 声明（taskbox 不替代声明）
- 域 owner 对任务有异议 → 投 mailbox/ 对应收件箱（复用现有异议通道），本箱状态列标「异议」

## 条目格式（维护者投递填写）

```
行号（域内自增） | 日期 | 任务摘要（一句） | 引用（backlog 行号 / plans 文件，无引用 = 未立项） | 建议分支 | 依赖 | 验收口径 | 状态
```

- **状态机**：`待认领` → 域 owner 开工改 `进行中` → 合入 master 后维护者标 `✅` 销号（与 mailbox 闭环一致）；异议 → 状态标 `异议` + 投 mailbox 对应收件箱
- **单一事实源**：任务详情主写在 doc/plans/ 或 backlog，本箱行只做摘要 + 指针，防双源漂移
- **行号引用铁律**：任务必须带 `[B-<序号>]`（backlog）或 plans 文件引用

## 规则

1. **单向可写**：维护者独占追加行；域 owner 仅改自己任务的「状态」列（行级更新，git 物理隔离合入零冲突）
2. **投递即分派**：backlog 状态 assigned 时投递，不等域 owner 批复；域 owner 在下次同步点前认领或异议
3. **销号**：任务合入 master 且验收通过后维护者标 ✅；同一任务不删行，保留分派-完成全程
4. **不投本箱的**：跨域声明（mailbox）、需求登记（backlog）、交付记录（records/<域>.md）、共享面契约（records/shared.md）
